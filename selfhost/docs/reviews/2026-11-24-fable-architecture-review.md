# Architecture review — PLAN-SELFHOSTED.md (DRAFT v1)

Reviewer: arch-review-fable (independent, read-only) · Baseline checked: upstream v0.1.9 (`e6c1c53`), unmodified checkout.
Method: every upstream claim was checked against source. Nothing was executed (no git, npm or tests), and `node_modules/` is absent, so statements about Node/undici runtime behaviour are from knowledge, not from a run; they are marked "unverified here".

## (A) Verdict

The overall shape is sound and most upstream facts in the plan are accurate: wrapping `startServer`, a localStorage-boundary agent, SQLite, an outbox, and a merge-based fork all fit this codebase. The plan is **not ready to implement as written**. Two critical defects sit in the sync design: the URL hash overrides a hydrated workspace on every reload, which combined with "auto-reload when hidden" produces reverts and a reload ping-pong; and the inlined snapshot has no escaping rule, which turns third-party community script code into stored XSS on the authenticated origin. The alert design has concrete lost-push, duplicate-push and resurrected-alert scenarios, because `arm_gen` is derived from observed `active` transitions on whole-array writes. The market-hours design depends on signals (`m`, `marketState`) that `QuoteStream` and `/api/yahoo/quotes` do not expose. Importing browser code into the server process converts browser-tolerated handler exceptions into process crashes. The sync workflow runs untrusted upstream code in a job that holds a write PAT. All of these are fixable without abandoning the zero-upstream-edit goal; several fixes are simplifications (see D).

## (C) Claims verified as correct

## (D) Simpler alternatives worth considering

1. **Make the native quote adapter the only quote source; drop the shim (ADR-006).** The plan already commits to building and testing the adapter "from day one". What `QuoteStream` adds for alerts is small: the WebSocket loop is a fixed 3 s retry alternating hosts (`datafeed.js:846-857`, `:867-879`); the 429/418 backoff the ADR cites applies to REST only (`:88-110`). Using it costs a globals shim, a contract test, a second implementation, the crash exposure in F6, the missing `m` flag in F5 and the memoized mode in F17. One adapter with guarded handlers (Binance miniTicker, Coinbase ticker, loopback Yahoo SSE with `m`) removes five findings.
2. **Loopback HTTP proxy instead of listener capture (ADR-001).** Since the internal listener exists anyway, the public server could `http.request` to it and pipe. That depends only on documented behaviour and removes the "exactly one request listener" contract. Listener capture is acceptable as planned; this is the fallback that needs no upstream PR.
3. **No `main` mirror and no mirrored tags (ADR-010).** Fetch `upstream` (with tags) inside the sync job and merge the tag from there. `is-ancestor` works on fetched refs. This removes the mirror push, the tag pushes that match `release.yml`, the "upstream force-pushed" branch, and most of F15.
4. **Do not sync `workspace`'s active symbol/timeframe, or do not sync `workspace` at all initially.** It is the key with the worst behaviour (F1, F9) and arguably per-device state. Syncing watchlist, scripts, drawings, alerts, appearance and paper delivers most of the value.
5. **Outbox holds dirty keys only** (F21) and **per-key version entries** (F8): less code and fewer races than blob-in-blob.
6. **`/api/health` stays authenticated; only `/api/health/ready` is open** (F11): one fewer exception and no version disclosure.
7. **Use undici's `EventSource` for the worker** if any SSE client is needed in Node — undici is already the one runtime dependency. Unverified here (`node_modules/` is not installed); confirm the pinned version exports it.

## (E) Missing questions for the owner

1. Should the active chart's symbol/timeframe (and `workspace` as a whole) follow you across devices, or is that per-device state? (F1, D4)
2. On a conflict between a stale device and newer server data, which loses: the stale device's edit (compare-and-swap) or the newer data (LWW)? The plan defaults to the latter, including for the paper account and scripts. (F9)
3. Is running two devices' main windows at once expected? Both will evaluate paper fills and alerts independently; paper results can differ by tick.
4. How many alert symbols on Yahoo do you expect? Above 100 needs extra work. (F13)
5. Should alerts fire in pre/post-market at all, given upstream mixes extended-hours ticks with regular-session poll prices? (F5; this sharpens plan question 3)
6. Will the container run with host networking on Unraid? If so the "internal" loopback listener is reachable, unauthenticated, by every process on the host.
7. Will access be through Tailscale Serve or another reverse proxy? That decides `TRUST_PROXY`, cookie `Secure`, and whether per-IP limits mean anything. (F20)
8. Is HTTP/2 or HTTPS available on the LAN path? If not, the six-connection limit is a hard constraint on pop-outs. (F8)
